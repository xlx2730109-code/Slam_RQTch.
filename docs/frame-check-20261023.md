## 同一批姿态的离线对比

保留文件位于`evidence/2026-10-23/frame-check/`。通过直接TCPROS订阅采集，没有注册新ROS节点、发布指令或写远端文件。位姿8秒、IMU2秒及速度1秒依次采集，不能当成严格同步录包。静止检查未附独立位置、角度真值，不能从本表估算真实机器人运动。

| 指标 | 结果 |
| --- | --- |
| 位姿样本与时间跨度 | 97帧，8.0207秒 |
| 位置XYZ范围 | 0.01035、0.01202、0.00712m |
| 完整三维姿态相对首帧最大变化 | 0.5646° |
| 原始传感器X轴航向范围/标准差 | 25.5515° / 6.3689° |
| 传感器Z轴投影航向范围/标准差 | 0.5705° / 0.1494° |
| X轴水平投影最小长度 | 0.02729 |
| Z轴水平投影最小长度 | 0.99973 |
| 随后506条IMU的平均加速度 | `[9.80955, 0.13386, 0.08262]m/s²` |
| 速度话题1秒窗口 | 未收到消息，不证明遥控器一定没有动作 |

现有航向计算投影传感器X轴。该轴接近竖直，水平投影很短，小的三维姿态变化会产生大的投影角变化。传感器圆形顶部对应的Z轴接近水平，以其投影计算可消除本批数据中主要的几何放大。

这验证的是坐标提取问题，不是完整SLAM精度、实际角度真值或全程稳定性。前后两个安装方向的Z轴符号相反；仅有静止姿态和重力时仍存在180°歧义，不可擅自选择符号。

## 候选转换及实际修复边界

`frame_candidate.py`仅是离线候选，未纳入任何运行启动脚本。给定传感器系中的车身前向与上向，用叉乘构造左向；点坐标按该安装基转换，姿态按旋转复合处理。前向Z、后向负Z及上向X的两组候选均经过右手性、方向、错误输入及本批实测样本检查，共6项通过。

需要统一检查以下使用者，不能只修网页显示：

| 原机文件 | 后续工作 |
| --- | --- |
| `jiaoda/pose_bridge.py` | 输出车身姿态，明确实际参考点与坐标含义 |
| `jiaoda/console_backend.py` | 显示与导航采用相同车身姿态 |
| `jiaoda/grid_bridge.py` | 保持地图、位姿和显示箭头一致 |
| `jiaoda/nav_simple.py` | 雷达点先转车身坐标，再做高度、车体过滤和世界坐标变换 |

还需确认前后设备映射、雷达相对参考点的位置、控制方向和停止行为。当前没有修改IMU与雷达内部外参，也没有修改点内时间单位、导航参数或原地图。旧审计中的时间单位疑点仍需独立回放验证。

本轮是试跑前诊断，没有建图行驶、自动到点或拍照验收成绩。网络配置、代理、VPN、路由、机器人服务均未由本轮修改或重启。
